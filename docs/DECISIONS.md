## Telegram bridge safety
Telegram uses existing D2K tunnel. Do not alter D2K, DoQ, routing or firewall for the bridge. Router-local HTTPS probe is required before and after future WG apply; if baseline OK becomes FAIL, do not confirm transaction and roll back owned WG changes. HTTPS reachability is not bot authentication. Bot command allowlist: status, version, wg-status; future wg-start/stop only for a fixed owned interface, authenticated owner, no arbitrary arguments or shell execution. No restart of unrelated services. If Telegram fails, evaluate an authenticated outbound relay first; Cloudflare Tunnel is another option for a restricted management endpoint, never expose SSH or raw shell.
